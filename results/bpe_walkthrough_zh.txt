BPE 逐步演示
机制分析用微型字节级 BPE；不是训练 GPT-4，也不代表 cl100k_base 的真实切分。
MinBPE 固定提交：1acefe89412b20245db5a22d2a02001e547dc602
本实验没有随机步骤。

一、训练：abababab，词表大小 259 = 256 个基础字节 + 3 次合并
第 1 轮：
  合并前 ID：[97, 98, 97, 98, 97, 98, 97, 98]
  合并前片段：['a', 'b', 'a', 'b', 'a', 'b', 'a', 'b']
  所有相邻 pair 计数：
    [97, 98] ['a', 'b']：4 次
    [98, 97] ['b', 'a']：3 次
  选择：[97, 98]；统计频率 4
  实际非重叠替换：4 次
  新 ID 256 = 'ab'；字节 [97, 98]
  合并后 ID：[256, 256, 256, 256]；片段 ['ab', 'ab', 'ab', 'ab']

第 2 轮：
  合并前 ID：[256, 256, 256, 256]
  合并前片段：['ab', 'ab', 'ab', 'ab']
  所有相邻 pair 计数：
    [256, 256] ['ab', 'ab']：3 次
  选择：[256, 256]；统计频率 3
  实际非重叠替换：2 次
  新 ID 257 = 'abab'；字节 [97, 98, 97, 98]
  合并后 ID：[257, 257]；片段 ['abab', 'abab']

第 3 轮：
  合并前 ID：[257, 257]
  合并前片段：['abab', 'abab']
  所有相邻 pair 计数：
    [257, 257] ['abab', 'abab']：1 次
  选择：[257, 257]；统计频率 1
  实际非重叠替换：1 次
  新 ID 258 = 'abababab'；字节 [97, 98, 97, 98, 97, 98, 97, 98]
  合并后 ID：[258]；片段 ['abababab']

二、编码新文本：ababab；沿用已有规则，不重新训练
  [97, 98, 97, 98, 97, 98] --规则 rank 256--> [256, 256, 256]
  [256, 256, 256] --规则 rank 257--> [257, 256]
  完整解码：'ababab'

三、重叠计数：aaa 中 aa 有 2 个相邻位置，但一次只能替换 1 对，得到 [256, 97]。

四、编码 rank 与频率的反例
新文本中 ab 出现 1 次、bc 出现 4 次；编码仍先合并 rank 为 256 的 ab，不是先合并更频繁但 rank 为 257 的 bc。
  训练语料：ab1ab2ab3ab4bcbcbc
  新文本：abcbcbcbc
  最终 ID：[256, 99, 257, 257, 257]

五、字符不等于字节；完整 token 序列才能可靠解码
  '你好'：2 个 Unicode 字符，6 个 UTF-8 字节 [228, 189, 160, 229, 165, 189]；往返一致。
  'é'：1 个 Unicode 字符，2 个 UTF-8 字节 [195, 169]；往返一致。
  '🙂'：1 个 Unicode 字符，4 个 UTF-8 字节 [240, 159, 153, 130]；往返一致。
  '你好，España! 🙂'：12 个 Unicode 字符，22 个 UTF-8 字节 [228, 189, 160, 229, 165, 189, 239, 188, 140, 69, 115, 112, 97, 195, 177, 97, 33, 32, 240, 159, 153, 130]；往返一致。

  [通过] 空文本可编码并还原
